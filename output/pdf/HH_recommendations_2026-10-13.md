Подготовлено 13 октября 2026 года. Основа: обе предоставленные версии резюме и полная автоматическая расшифровка [ролика «я ПРОНИК в кабинет HR рекрутера. Они видят ВСЕ»](https://www.youtube.com/watch?v=0J6eOt72Ko0), 24:52. Разбор выполнен по расшифровке публичного оригинала; это не покадровая проверка локального MP4. В автоматических субтитрах есть ошибки распознавания названий технологий.

## Что изменено

Сохранены исходные компания B2B SaaS, период сентябрь 2023 - сентябрь 2026, три года опыта, стек и все численные результаты. Опыт не заменён проектным. Удалены плашки о макете и соответствующее описание в метаданных новых PDF. Убрано пустое место для фотографии. Из двух страниц собрана одна: повторяющиеся технические задачи объединены, достижения подняты непосредственно под описание работы. В начале явно указана специализация Python Backend и три года опыта. Английская версия согласована с русской по содержанию работы.

Видимые числа сохранены без усиления: 74 → 11 запросов, 920 → 240 мс p95, 87% строк кода, 40 → 10 минут на релиз. Это данные исходного резюме; отдельная проверка измерений не проводилась.

## Готовые поля для hh

**Название:** Python-разработчик / Python Backend Developer.

**Специализация:** Программист, разработчик.

**О себе:**

Python backend-разработчик с 3 годами опыта в B2B SaaS. Разрабатываю REST API на Django/DRF и FastAPI, оптимизирую PostgreSQL, реализую интеграции и фоновые задачи на Celery/RabbitMQ. Веду изменения от требований до релиза и поддержки. В работе уделяю внимание производительности API, надёжности интеграций и автоматизированному тестированию. Рассматриваю удалённую работу в backend-разработке.

**Ключевые навыки для выбора в интерфейсе:** Python, Django, Django REST Framework, FastAPI, PostgreSQL, SQL, REST API, Redis, Celery, RabbitMQ, Docker, Git, Linux, pytest, asyncio, SQLAlchemy, Pydantic, Docker Compose, GitHub Actions, CI/CD, HTTP, JWT. Если интерфейс предлагает стандартный тег, выбирать его. JavaScript и React оставить дополнительными навыками, если они нужны вакансии.

**Опыт:** перенести должность, даты, описание компании и четыре результата из обновлённого RU-резюме. Для вакансий с упором на PostgreSQL начинать с оптимизации API; для интеграционных сервисов - с Celery и webhook; для платформенных команд - с выпуска изменений и тестов. Не менять остальные результаты только ради новых формулировок.

**Образование:** Костромской государственный университет, «Информационные системы и технологии», бакалавриат в процессе обучения. Уточнить ожидаемый год окончания вместо одного только указания курса, когда он известен.

**Текст для сопроводительного письма:**

> Здравствуйте! Заинтересовала вакансия Python-разработчика в [компания]. У меня 3 года опыта в B2B SaaS: Django/DRF, FastAPI, PostgreSQL и Celery. Для ваших задач по [требование вакансии] особенно релевантен мой опыт [один подходящий результат из резюме]. Пример проекта: eidosacademy.ru; код: github.com/Middlewarer/EidosAcademy. Буду рад обсудить задачи команды. Связаться со мной: [Telegram или email].

Квадратные скобки заменить перед отправкой. Полные тексты новых резюме для копирования: [RU](./Alexey_Python_Backend_RU_Revised.txt), [EN](./Alexey_Python_Backend_EN_Revised.txt).

## Что ещё нужно добавить перед откликами

1. Фамилию и прямой канал связи: email и/или Telegram, при необходимости телефон. Сейчас есть только имя и GitHub. Это самое заметное препятствие для быстрого контакта.
2. Актуальное место проживания: в RU сохранена Кострома, в EN - Бельцы. Если документы относятся к одному текущему месту проживания, привести их к согласованному виду. Город поиска и место проживания заполнять отдельно по смыслу полей.
3. Название работодателя вместо общего «Продуктовая компания, B2B SaaS», если его можно раскрывать. Конкретное название даёт контекст. Если есть ограничение на раскрытие, описать его только при наличии такого ограничения.
4. Уровень английского. Он особенно нужен в EN-версии и в структурированном поле hh. Уровень не выводится из наличия переведённого резюме.
5. Доступность для полной занятости, часовой пояс и возможную дату выхода, если это помогает ответить на вопросы конкретного работодателя. Учёбу и рабочий график согласовать заранее.

## Что подготовить к разговору по достижениям

Для результата 74 → 11 и p95 920 → 240 мс: объяснить исходный endpoint, причину N+1, изменения ORM/SQL, выбранные индексы, набор данных и метод измерения нагрузки. Для 87%: назвать измеряемый код, инструмент отчёта, исключения из покрытия и критические сценарии. Для релиза 40 → 10 минут: описать этапы до и после автоматизации, ручные действия и поведение при ошибке миграции. Для webhook: объяснить ключ уникальности, границы транзакции и повторную доставку события. Эти детали делают уже указанные результаты понятными техническому интервьюеру.

## Как оценивать эффект

Вести простую таблицу: вакансия, стек, регион/страна, дата, версия резюме, ответ, приглашение, результат технического этапа. Сравнивать сопоставимые вакансии за одинаковое время ожидания ответа. Менять по одному элементу: порядок достижений, первый абзац или сопроводительное. Небольшое число откликов не позволяет надёжно судить о причине отказов.

## Проверенные источники hh

Официальное описание [языка поиска hh](https://hh.ru/article/25295) подтверждает отдельный поиск по должности, навыкам, работодателю и описанию работы. Поэтому технологии присутствуют и в тегах, и в контексте задач. Документ также описывает нормализацию и синонимы: не нужно многократно повторять один термин ради плотности ключевых слов.

Официальная [страница авторазбора](https://feedback.hh.ru/knowledge-base/article/9110) описывает отбор по параметрам и вопросы бота. Редакционные [рекомендации hh по навыкам](https://career.hh.ru/article/professionalnye-navyki-v-rezyume-chto-mozhno-i-nelzya-pisat) предлагают связывать инструменты с задачами и результатами. Это основания для структуры, а не подтверждение гарантированного рейтинга или приглашения.
