# Job Search OS · HARD MODE

Локальный учебный трекер Python backend. Запуск: `start-learning.cmd`.
`start-job-search.cmd` открывает только ручной журнал откликов.

## Календарь

Старт — **2 октября 2026**, цель выхода на работу — **15 декабря 2026**.
Оффер зависит от работодателя: это целевая дата, не гарантированный прогноз.

Рабочая нагрузка — 9 часов шесть дней в неделю, перерывы отдельно;
воскресенье без новых тем. Счётчик учитывает только реальное время фокуса.
Цель можно изменить в Pomodoro; пропуски не компенсируются бессонной работой.

| Этап | Даты |
| --- | --- |
| Быстрый фундамент всех базовых треков | 02.10–14.10 |
| Python Core и первый Django параллельно | 15.10–31.10 |
| Рабочий backend и завершение Python | 02.11–16.11 |
| Production, углубление и Asyncio/FastAPI | 17.11–09.12 |
| Резерв до целевой даты | 10.12–15.12 |

В обычный день: до 445 минут нового материала с практикой, 75 минут
независимых проверок и ровно 20 минут на короткую HH-разминку. Остаток до
540 минут отводится на закрепление, проектное доказательство или закрытие
ранней незавершённой темы — не на дополнительные отклики. Повторение и
практическая проверка (45 минут) входят в общий блок проверки.

Больших дней поиска работы и пустого спринта без новых тем больше нет.
Все десять направлений имеют собственную dependency-first очередь: практичные
темы могут идти раньше своего исторического номера, при этом стабильные ID и
старый прогресс сохраняются. После короткого фундамента поздний Python Core,
Django, SQL, HTTP и pytest идут параллельно. Docker подключается с первым API,
а production-темы и Asyncio/FastAPI закрываются общей финальной волной.
Основная программа заканчивается 9 декабря, оставляя шесть учебных дней до
целевой даты на долги, проекты, собеседования и повторение.

Все 240 тем сохранены, а число обязательных заданий сокращено до 384:
на тему приходится одна короткая теория и максимум одна практика. Алгоритмы
остаются отдельным треком и начинаются только после Python Core; в обычные
уроки Python задачи LeetCode больше не подмешиваются. Порядок подтем внутри
направлений не меняется. Завершённая тема сразу и окончательно учитывается в учебном
прогрессе. Фактические даты старых попыток не переписываются.

## Дисциплина

На главном экране ежедневно меняется конкретное правило работы:
собственная попытка до подсказки; результат + проверка + объяснение;
ошибка с причиной, исправлением и повторной проверкой. Без мотивационных
лозунгов и автоматического списания долгов.

## Собеседования

Семь форматов: диагностика, техническое интервью, live coding, SQL,
отладка инцидента, защита проекта, HR/самопрезентация.
Диагностика доступна сразу, даже без завершённых тем.

Промпты задают вопросы по одному, ограничивают уточнения, исключают
смысловые повторы и включают журнал ранее заданных вопросов.
Промпт копируется вручную в нейросеть: само приложение не делает сетевых
запросов и не гарантирует поведение сторонней модели.

После попытки сохраняются четыре оценки по 0–25, реальные вопросы,
разбор/артефакты, ошибки и отметки о подсказках/критической ошибке.
Зачёт формата: сумма ≥85, каждая шкала ≥18, без подсказок и критической
ошибки. Диагностика не является зачётной попыткой.
Это пользовательский отчёт, а не независимая сертификация.

Ошибки создают повторы через 1, 3 и 7 календарных дней. Повтор закрывается
отдельным описанием нового решения и проверки. История старых интервью
остаётся доступной. Результат интервью не меняет матрицу навыков.

## Остальные разделы

Матрица навыков сохранена как обзор завершённых тем без отдельного статуса
подтверждения. Учебные промпты, проекты, резюме, недельный отчёт
и Pomodoro сохранены. Проект доказывается по отдельным этапам, а не самим
наличием репозитория. Ручной журнал откликов не связан с внешними сервисами
и не является обязательным учебным блоком.

Интеграция HH, лента вакансий, импорт, расширение и генератор сопроводительных
удалены из активного приложения. Код и личные снимки перенесены в
`backups/retired-hh-20261002` (папка игнорируется Git).
Почасовое расписание остаётся отключённым.

## Сохранность данных

Данные: `%USERPROFILE%\.eidos_learning_tracker\progress.json`.
При первом запуске этой версии создаётся
`progress.before_hard_mode.json`; сохранение остаётся атомарным, с защитой
от второго писателя и копией `progress.last-good.json`.

Импортированные записи вынесены из активной воронки в
`integration_archive` внутри прогресса. Они не участвуют в метриках,
но остаются восстановимыми. Ручные записи, задания, заметки, доказательства,
попытки, резюме и история фокуса не удаляются.
